## 官方任务目标

输入两个有顺序的短语，判断它们属于正向蕴含 **F**、反向蕴含 **B**、等价 **E**，还是其他关系 **N**。交换输入后，可逆关系的预测应满足 **F ↔ B、E ↔ E**。官方同时考察分类是否正确、正反方向是否一致：**Weighted F1** 衡量逐行分类质量，**SoftCons** 衡量正反预测是否相容，**HardCons** 要求一组的两个方向都答对。后两项只计算 F/B/E 可逆组。

任务覆盖英语、西班牙语、巴斯克语及混合语言四个赛道。本项目目前研究 **Track 1（英语）**，官方 Train 为 **3042 行**，Dev 为 **660 行**。

## 实验过程

项目从 BERT 四分类开始，逐步尝试方向约束、词级比较、数据增强和模型融合。下面按主要改动分成 **14 个阶段**，同类尝试放在一起；后期有些实验同时进行。除特别注明外，成绩均为官方 **660 行 Dev** 上的 Weighted F1。

**成绩说明：** independent 按每行的四类最高分预测；pair-aware 联合正反两行的分数再预测。表中同一行的两项成绩使用同一个模型或同一组融合分数。实验的选模方式和部分训练设置有所不同，因此分数变化不一定只来自列出的那一项改动。`—` 表示没有找到可核对的成绩。

### 1. BERT baseline：从四分类开始

- **改动：** 两个短语联合输入 BERT-base-uncased，取 `[CLS]`，接 Dropout 和四分类层。用官方 3042 行、普通交叉熵训练；**Row CE** 就是逐行对 F/B/E/N 计算分类损失。
- **问题：** 训练只要求当前输入答对，没有额外检查交换顺序后的答案，也没有单独比较两边的词语。
- **结果：** BERT 的历史 Dev 分数没有完整记录，这里记为 **—**。随后换用 DeBERTa，比较不同编码器的效果。

代码：[BERT baseline](experiments/baselines/bert_baseline.py)。

### 2. DeBERTa 四分类：更换编码器

- **改动：** 用 `microsoft/deberta-v3-base` 替换 BERT，仍采用“联合编码 → CLS → 四分类”，训练数据保持官方 3042 行。
- **成绩：** 保存的独立 F1 为 **0.8438**。
- **问题与下一步：** 两个方向分别预测时，可能一边判 F，反过来却判 E。为减少这类矛盾，下一步把两个方向的分数合起来判断。

代码：[DeBERTa baseline](experiments/baselines/deberta_baseline.py)。

### 3. Pair-aware：预测时合并两个方向

- **改动：** 对同一 pair 的正反两行比较 `F₁+B₂`、`B₁+F₂`、`E₁+E₂`，输出最高的 FB／BF／EE。相加的是模型分数；**不更新参数，单例仍由模型四分类**。
- **成绩：** 早期 DeBERTa 的 independent **0.8438**，联合解码后约 **0.8977**。
- **问题与下一步：** 两个方向虽然一致了，仍可能一起选错关系。这一步只修改预测，训练目标还没有要求整组答案正确。下一步就在训练时加入组合监督。

相关实现：[DeBERTa baseline 的联合预测](experiments/baselines/deberta_baseline.py)、[原版 pair_aware 函数](experiments/deberta_original/train.py)。

### 4. Pair CE → Real Pair CE：把组合判断用于训练

- **改动：** Pair CE 把 FB／BF／EE 当作三个候选答案，用正确组合计算交叉熵并更新参数。最初临时交换输入，后来直接读取同一 `pair_id` 的两条记录，每组训练一次，避免重复构造已有的反向样本。
- **训练安排：** 每轮先对所有行训练 Row CE，再对真实组训练 `0.5 × Pair CE`。这是两个连续阶段，不是每个 batch 都把两个损失相加。
- **后续调整：** 增加 N／EE 类别权重，换 NLI 初始化，加入 Pair 标签平滑。后面的 Token Alignment 版本沿用了这些设置。

这里的 NLI 初始化使用 `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli`。它已经接受过蕴含任务训练，我们再接上新的 F/B/E/N 分类头，适应 DiCo 的标签。

这些设置分别改变什么：

- **类别权重**：提高某类样本算错时在损失中的权重。N 的权重作用于 Row 四分类；EE 的权重作用于 Pair 三分类，两者不同。
- **标签平滑**：正确组合仍是主要目标，但给其他组合留少量目标概率，减轻训练时过度自信。
- **学习率调度**：这里先用前10%的更新步逐渐提高学习率，再线性降低；原版固定学习率不做这个变化。
- **类型辅助任务**：把 F/B 合成“有方向的蕴含”，再与 E、N 区分；**方向辅助任务**只对 F/B/E 额外分类，不把 N 送进该辅助头。

| 尝试 | pair-aware F1 | 结果说明 |
|---|---:|---|
| 临时交换输入的 Pair CE | 0.8966 | 未明显超过只做联合解码，改为真实组训练。 |
| Real Pair CE | 0.9030 | 保留按真实 pair 分组的训练方式，继续分析 N 和 E 的错误。 |
| N 的 Row 权重 1.5 | 0.9078 | 保留；加到 1.75 的运行约 0.8964，没有继续加大。 |
| EE 的 Pair 权重 1.25 | 0.9124 | 保留，增加等价组监督权重。 |
| NLI 初始化 DeBERTa-base | 0.9133 | 采用 MNLI／FEVER／ANLI 微调过的编码器，另接本任务的四分类头。 |
| Pair label smoothing 0.05 | 0.9160 | 沿用 0.05，让目标分布不过于集中在正确组合上。 |
| 学习率调度变体 | 0.8839 | 低于当时保留的配置，后续没有采用。 |
| 类型／方向辅助任务 | 0.8929／0.9089 | 没有超过当时的主要配置；方向输出校准曾得 0.9118。 |

**问题与下一步：** 加权和组合训练后，模型仍容易把等价改写当成单向蕴含，或忽略新增的限定。接下来让它直接比较两边的 token。

代码：[Pair 训练](experiments/pair_training)、[辅助任务](experiments/auxiliary)。早期单项结果见[完整实验记录](docs/history/DICO_NLI_FINAL_EXPERIMENT_RECORD.md)。

### 5. Token Alignment：逐词比较两个短语

- **改动：** token 表示从 768 维投影到 128 维，双向软对齐；比较自身、对齐表示、差值、乘积，经 mean／max pooling 得到修正 logits，与 CLS logits 相加。
- **代表成绩：** 官方 **3042 行，无 Lexical、无增强**，同一第 7 轮 independent **0.5280**、pair-aware **0.9248**。后面所说的“原版 0.9248”就是这一配置。独立分与联合预测分的差距，在第 9 阶段进一步分析。
- **问题：** 找到对应位置后，模型仍可能误判这个差别是否改变意思。另外，原版每个 token 都要从对侧取匹配表示，即使没有合适的对应词也一样。

围绕对齐和分类方式，还做了以下尝试：

表中的结构名称：

- **软对齐**：每个 token 按相似度加权参考对侧多个位置；不是固定选一个对应词。**均匀对齐**则把对侧有效位置等权平均。
- **NULL／空匹配**：让某个词可以选择“对侧没有合适对应词”。NULL 是匹配选项，不是 N 类标签。长度归一化版还尝试减少不同文本长度对匹配强度的影响。
- **mean／max pooling**：前者取各有效 token 特征的平均，后者逐维取最大值。**Attention pooling**改为学习每个位置的汇总权重。
- **原型分类头**：每一类设置一个或多个可训练代表向量，根据输入与它们的相似度分类；k 表示每类的代表向量数。
- **ReLU／GELU**：神经层使用的两种激活函数。**分组学习率**指主干与新增分支采用不同学习率。
- **早期 contrast**：历史记录描述为使用少量已核验的关系对照加排序损失，让正确关系比竞争关系得分更高；它与第7阶段Qwen的同标签对比学习不是同一个实现。

| 变体 | pair-aware F1 | 结果说明 |
|---|---:|---|
| NULL-M，seed42／seed7 | 0.9290／0.9101 | 增加“无匹配”选项；seed42 高于原版，seed7 的结果较低。 |
| 其他 NULL／长度归一化变体 | 0.9019／0.9030／0.9123 | 低于原版 0.9248，保留为对照。 |
| 均匀对齐，seed42／seed7 | 0.9151／0.8913 | 低于原版，继续使用可学习的软对齐。 |
| Attention pooling | 0.9198 | 换汇总方式没有进一步提高。 |
| 早期局部组合变体 | 0.9187 | 未超过原版，不作为默认。 |
| GELU／分组学习率 | 0.9246／0.9192 | 分数没有提高，继续使用原来的 ReLU 设置。 |
| 原型分类头 k=1／k=3 | 0.9087／0.8987 | 换分类头后分数下降。 |
| 早期 contrast 变体 | 0.9259 | 这次略高于原版，尚缺多种子验证。 |

**后续：** 继续使用普通 Token Alignment，NULL 等版本单独保留。接下来补充词汇覆盖、数字和否定等特征，看这些明确的差异能否帮助分类。

代码：[原版训练](experiments/deberta_original/train.py)、[对齐变体](experiments/alignment)、[辅助分类头](experiments/auxiliary)。

### 6. Lexical 与词义知识：加入可计算的差异特征

- **改动：** 提取双向覆盖率、长度、集合包含、数字、否定等 **20 维**特征，经 `20 → 32 → 4` 分支产生修正分数，与原分支相加，共增加 **804 个参数**。这些特征如何影响答案，由分类损失训练得到。
- **问题：** 词语被包含、文本更长，都不能直接确定蕴含方向；WordNet 查到的关系也可能不是当前片段里的词义。为此又加入差异位置特征，并尝试用上下文门控控制词典知识的使用。

**ALTN、WordNet、KIM 和门控分别是什么？**

- **ALTN式差异位置特征**：借鉴[ALTN词对齐特征论文](https://aclanthology.org/S13-2023/)描述“哪些片段没有对上”的思路。本项目先用最长公共子序列（LCS）对齐相同的词，再分别统计两侧的未匹配片段数、最长片段长度、首个和末个差异位置，每侧4个数，共8维。例如 `a red truck / a truck` 中，`red` 是未匹配部分。它记录差异的位置，不判断差异的含义；同义改写也可能被记成未匹配。这里不是跨语言ALTN系统的完整复现。
- **WordNet**：一种[英语词义关系词典](https://wordnet.princeton.edu/)，按词义记录同义、上下位、反义等关系，例如 car／automobile 的同义关系、car／vehicle 的类别包含关系。本项目去掉共有词后，查询差异词，把关系覆盖率等统计成新增12维特征，与原20维Lexical一起使用。它不是另一个生成模型，也不直接给 F/B/E/N 答案；本实现没有自动根据上下文消歧，可能选错词义。
- **KIM式局部知识交互**：借鉴[外部知识增强NLI论文](https://aclanthology.org/P18-1224/)，仍从WordNet查询，但不只汇总成整句统计。每个候选词对附上4种关系：同义、左词更具体、右词更具体、反义，再沿原Alignment权重汇总，送进token比较层。WordNet特征版告诉模型“这对短语有多少词典关系”，KIM式版本进一步保留“哪些词之间有关系”。这里也只借鉴了局部知识融合。
- **上下文门控**：在KIM式版本上，为每个词对的每种词典关系算一个0—1权重，再乘到关系特征上。接近0表示少用，接近1表示多用；权重由两词的上下文表示和关系共同计算，并通过训练学习。目的是减少不适用于当前片段的词典知识，但高门值本身不证明知识正确。它与第14阶段负责提供 `p(N)` 的“N门”不同。
- **门控学习率调整**：run01门控与主干同用 `2e-5`；run02只将门控学习率改为 `1e-3`，知识投影仍为 `2e-5`。不是又加了一个新门。
- **Pair权重调整**：表中这次改的是损失前的总系数 `0.5 → 0.75`，不是把FB／BF／EE的类别权重改成0.75。

|---|---:|---:|---:|---|
| Lexical 第一版 | 3042 | 0.5542 | 0.9214 | 结构分未超过原版，继续调整新分支学习率。 |
| Lexical 分支 lr=1e-3 | 3042 | 0.4682 | 0.9306 | 结构分达到 0.9306，独立分仍低；后续作为词汇版对照和融合成员。 |

### 7. 其他模型与 Qwen：比较编码器和生成式模型

- **改动：** 一方面比较不同编码器／初始化，另一方面用 Qwen LoRA 做标签生成。Qwen 主线采用短 Prompt、completion-only SFT、`r=16 / alpha=32`，**训练不含 Pair CE，预测后再做 pair-aware**。
- **数据变化：** Qwen C 使用官方 3042 行＋475 条筛选后的反向 N，共 3517 行。这 475 行是按本项目规则构造的增强样本，反向 N 标签并非官方提供。

这里的几个名称：

- **NLI**是自然语言推断；表中的NLI初始化已在蕴含相关数据上微调过，原始base没有这一步。
- **base／large／xsmall**表示不同模型规模；**zeroshot初始化**是另一份预训练权重的名称，本实验仍对它进行DiCo微调，不是直接零样本预测。
- **Prompt**是输入模型的任务说明；**SFT**是用标准答案做监督微调。completion-only表示只对答案及结束标记算损失，不让模型背诵输入说明。
- **LoRA**冻结原模型权重，额外训练低秩矩阵；r是这些矩阵的秩，alpha控制其缩放，详见第11阶段。
- **Qwen六类**将F/B/E保留，把N拆成相似SIMI、相关REL、相反OPPO，预测后再合回N。**二元蕴含读出**则分别判断两个方向是否蕴含，再组合成四类。
- **Token comparison**是给Qwen增加词级比较分类头；alignment版只用词级比较信息，global版再合入整体表示。
- **答案位置四类CE**只比较F/B/E/N四个候选分数；普通标签SFT是在完整词表中学习输出正确标签。**合法组合概率约束**鼓励正反预测的概率落在FB/BF/EE中，但它本身不指定哪一个组合正确。
- **监督对比损失**把同标签训练样本的表示拉近、不同标签的拉远；本次使用batch内对照，不等于专门检索了语义相近的难负例。**R-Drop**则比较同一输入在两次随机dropout下的输出，详见第11阶段。
- **检索示例**只从Train寻找相近样本，连同标签放进Prompt；随机示例版则随机挑Train样本，作为检索的对照。

| 原始 DeBERTa-base＋Alignment＋Lexical | 3042 | 0.4968 | 0.9103 | 结构 0.9103 低于同样含 Lexical 的 NLI 参考版 0.9306。 |

**新增数据与Dev怎么核对：**

**查什么？** 把实际用于训练的新增样本与Dev逐一比较：有没有相同的单词、词干、完整短语，以及整对文本。比较时忽略大小写、多余空格和两段文本的先后顺序。原Train与新增部分分开查，不能因为新增48行没有重复，就说整个3290行都没有重复。

**查出了什么？**

| 数据 | 与Dev核对的结果 |
|---|---|
| 官方Train | 本身就有7对文本与Dev重复，例如 `a baby / a small baby`。这些是原数据已有的，不是新增样本带来的。 |
| scope200 | 没有整对重复，但有相同单词和两个相同短语：`a brown horse`、`a horse`。 |
| relation48、人工80、事件200、边界120、局部128、semantic64、家族768 | 只看各批新增的训练行，单词、词干、完整短语和整对文本都没有查到重合。 |
| E改写88 | 没有整对重复，但有相同单词和9个相同短语。 |
| 各批copy | 复制的是原Train样本，所以会保留部分与Dev相同的词和短语；这些复制批次没有整对重复。 |

**这能说明什么？** 上表说明哪些文本重复、哪些没有重复。后期人工样本用Dev文本作排除名单，不用Dev标签替新样本标答案；但我们确实参考过Dev错误来决定补哪些类型，所以不能说增强过程完全没有参考Dev。早期manual-boundary构造时也参考了Dev，其0.9335不作为独立增强的证据。

因此，这里的结论是：**后期几批新增文本没有查到重合，但完整训练集仍保留官方Train已有的7对重复。** Test尚未公开，不能说与Test也没有重复。没有重复，也不代表人工标签一定正确。

**官方怎么规定？** 官方要求同一来源文本对的不同方向和语言版本放在同一个数据划分，并要求说明所用训练数据和外部资源。目前没有看到“出现相同单词就违规”的规定。官方禁止使用的是**最终Test不公开的正确答案**，也就是“隐藏评估标签”；公开的Dev答案不属于隐藏标签。我们用Dev评估、选模型和分析错误，但反复围绕Dev调整会让分数偏乐观，需要如实说明。官方Train已有的7对重复应向组织者反馈，不能把它说成我们新增数据造成的。[官方数据说明](https://github.com/ilopezgazpio/SemEval-2027-Task-2-DiCo-NLI#data-construction)、[官方数据使用规则](https://github.com/ilopezgazpio/SemEval-2027-Task-2-DiCo-NLI#competition-rules-and-terms)。

### 9. 分阶段评估与错误分析：独立分为什么低

- **改动：** 同一轮在 Row 后、Pair 后分别评估，记录 Train／Dev、N 误报与漏判、修好／破坏数量；补做不同种子、局部改写探针、重复输入与标签／语境检查。
- **发现一：训练阶段退化。** 原 0.9248 的 independent／pair-aware 为 **0.5280／0.9248**，非 N→N 共 **307 行**。原 0.938 的代表轮为 **0.5472／0.9381**，非 N→N 共 **297 行**。模型在四类中经常选 N，但排除 N 后，仍能区分不少 F/B/E 样本。
- **机制：** 三组合 Pair CE 不含 N；同一行 F/B/E 同时平移时，三组合概率不变，四类 argmax 却可能变化。它不能直接惩罚 N 压过正确的 F/B/E。因此，Pair loss 下降时，单行四分类仍可能退化。
- **发现二：训练集与 Dev 差距大。** 纯 Row 冻结版的同一权重 Train 独立 F1 **0.9974**、Dev **0.8485**；即使没有 Pair CE，也存在泛化错误。人工范围探针中“修饰归属改变”常被当 E，说明不能只靠修复训练退化解决全部问题。

**seed（随机种子）**控制参数初始化、样本打乱和dropout等随机过程。换seed用于检查结果是否依赖某一次随机训练；不是要求每次都取得相同最高分。

| 稳定性检查 | 结构／pair-aware F1 | 观察 |
|---|---:|---|
| 原 Alignment，seed42／seed7 | 0.9248／0.9124 | 单种子最高分不代表稳定水平。 |
| Lexical，seed42／seed7 | 0.9306／0.8876 | 这一配置换种子波动明显。 |
| NULL-M，seed42／seed7 | 0.9290／0.9101 | 不能仅凭 seed42 宣布替代原版。 |

**后续：** 先处理 Pair 阶段破坏单行预测的问题，再看模型对新表达的泛化。为此，在训练中持续保留四类监督，而不是只要求整组组合正确。

### 10. 调整 Row／Pair 训练：同时监督单行和整组

- **改动：** 在 Pair 阶段加 Row 回放、改为整轮混合训练、加入 NN 候选、改成反向 KL／hinge，或保护 Row 输出、参数和分类 margin；再试梯度投影、BLOOP 等协调主辅目标。
- **训练上的区别：** 混合训练同时改变了 batch 组成、更新次数和样本使用次数，不能把分差全算到损失公式上。NN 也分成“训练时加入”和“预测时允许”两项实验，反向 N 标签由本项目构造。

表里的目标与约束：

| 名称 | 在本项目中具体做什么 |
|---|---|
| 混合Row／Pair | 把真实Pair和N单例按组打乱；同一次前向中所有行算Row CE，有配对的行再算Pair CE。随机组批不保证每批都有N。 |
| 四组合／NN | 给Train的N单例构造反向N，把NN与FB／BF／EE放进同一个组合分类损失；预测允许NN则是另一项改动。 |
| 反向KL | 先把反向预测的F/B换回原方向，再用KL散度比较四类概率。KL度量分布差异，训练要求它们接近，但仍需Row CE教正确答案。 |
| 16组合hinge | 枚举两行四类的全部16种组合，让金标组合比最高错误组合至少高出一个margin；含N的错误组合也会被比较。 |
| N／非N门监督 | 只额外监督“这一行是不是N”，把剩余F/B/E组合判断交给Pair项。 |
| 参数锚定 | 记住本轮Row结束后的参数；每次Pair更新后把参数向这份参考拉回，限制偏移。 |

### 11. 冻结、LoRA 与正则化：减少过拟合和训练波动

- **改动：** 冻结部分层或只训练 N 头，用 LoRA 限制可训练参数；用后期参数平均、SAM、SiFT、R-Drop、Child-Tuning 检验稳定性和泛化。
- **问题：** 减少参数更新可能缓解过拟合，但不能补上输入缺失的语境，也不保证独立分和结构分一起提高。

这些方法怎样限制训练：

| 方法 | 含义与本项目做法 |
|---|---|
| 冻结／解冻 | 冻结的层仍参与前向，但不更新参数。底6层版冻结embedding与底部6层；top2版只开放最上面2层等指定参数继续训练。 |
| N头 | 在冻结模型的表示上新增二分类头，输出N概率；原F/B/E内部分数保持不变，用剩余概率分配给这三类。 |
| LoRA | 不更新原权重W，学习低秩增量BA；r控制低秩容量，alpha控制缩放。DeBERTa这组实验适配注意力的query／value投影，任务分类头仍训练；第7阶段Qwen主线则适配all-linear。 |
| SWA式参数平均 | 固定取第6—10轮Pair结束后的模型参数等权平均，最后预测只运行平均后的一个模型；不是多个模型投票。 |
| SAM | 先找附近使损失更高的参数位置，再在该位置求梯度更新，鼓励参数附近的损失更平缓，因此多一次前后向。 |
| SiFT式对抗正则 | 在归一化词表示上寻找会改变四类分布的小扰动，再约束干净与扰动预测接近；不改写文本，也不新增标签。 |

### 12. 分类头与组合结构：调整特征如何用于分类

- **改动：** 分别用 CLS 或 Alignment 做分类，再尝试对齐后 CNN、特征拼接、恢复 NLI pooler，以及同时编码两个方向的联合分类头。
- **为什么改：** 原版先让各分支分类，再把分数相加。这里改为让不同特征先交互，再分类，或把两个输入顺序的表示一起交给分类头。

分类结构的区别：

- **CLS单独／Alignment单独**：分别只让整对输入的总体表示或词级比较表示负责分类。
- **CNN组合**：在词级比较后加两层一维卷积，让相邻位置的差异先组合，再做汇总分类。
- **特征拼接**：将CLS的768维、Alignment的512维和Lexical编码的32维先拼成1312维，再经过同一个分类网络；原版是各分支先给四类分数再相加。
- **NLI pooler**：恢复原NLI模型中CLS后的dense＋GELU变换，再接本任务的新四分类层，不是复用原三分类答案。
- **双向联合头**：同一编码器分别处理 `(A,B)` 与 `(B,A)`，合并两次得到的表示后判四类；这与两个方向分别打分后做pair-aware不同。

### 14. 多模型测试：合并不同模型的预测

- **改动：** 各模型分别训练、保存选中的权重，再对同一批文本各预测一次，最后合并预测概率。模型之间不一起训练，也不合并模型参数。
- **为什么做：** 各模型错的样本不完全相同。单独低于 0.938 的模型，仍可能通过融合修好原模型的一部分错误。
- **早期结果：** Qwen四类＋六类概率融合结构约 **0.9022**；四类＋alignment约 **0.9076**。后来对97份去重成员分数比较普通、几何和分层融合，整理出16组代表组合，选择下列五组实现训练／预测。

**三种融合方式是什么意思？** 所有模型的输出先统一为 `F、B、E、N` 顺序，再按下面的方法合并。同一组中的成员等权参与。

- **普通平均（S01）：** 对每个标签，把各模型给的概率相加，再除以模型数。例如两个模型给F的概率是0.8和0.2，合并后F就是0.5。四个标签都这样算，再选概率最高的标签。平均的是每条样本的预测概率，不是模型的F1成绩。
- **几何平均（S11、S12）：** 对每个标签，把各模型的概率相乘，再开模型数次方，最后让四类概率之和变成1。代码用对数计算，避免许多小概率相乘后数值太小。它比普通平均更在意“有没有模型强烈反对”：某个模型给某类的概率接近0，会明显压低这类的合并分数；不代表它一定比普通平均好。
- **分层融合（S14、S16）：** 先由一个指定模型给出N的概率；其余模型只比较F/B/E，并对这三类的概率取平均。例如N模型给N为20%，其余模型平均认为非N时F/B/E分别占60%／30%／10%，最终四类就是 **F 48%、B 24%、E 8%、N 20%**。这里“N门”就是负责提供N概率的模型，不是把单例直接判N。

**融合后为什么还有两种成绩？** independent直接选择每行融合概率最高的标签；pair-aware再把正反两行一起判断，只允许FB、BF或EE。当前代码比较的是两行的**对数概率之和**，等价于比较概率乘积；单例保留融合后的独立预测。两列成绩来自同一套融合分数。

## 想向导师请教的问题

### 1. 数据增强可不可以做，需要注意什么？

目前尝试了人工构造的短语对照，例如属性增删、修饰范围、同义改写、动作角色等。scope200和relation48在已有实验中带来了提升，但后续扩大增强规模并没有持续提高，有些批次还不如复制原Train的对照。

想请教：这类人工增强是否适合作为论文方法？样本应该怎样构造、审核标签和控制数量？我们参考Dev错误选择了增强类型，再排除与Dev重复的文本，这种开发方式需要怎样披露，是否应该另设一份不参与设计的验证集？另外，本地官方Train与Dev已有7对重复文本，应该如何向组织者反馈、在实验中处理和报告？

### 2. 多模型共同预测是否可行，论文中应该怎样定位？

目前各模型分别训练，再合并预测概率。S14用6个模型分工判断：一个提供N概率，其余5个比较F/B/E，最后做pair-aware解码。本次实际预测的independent F1为 **0.545861**，pair-aware F1为 **0.962381**。

想请教：这种集成能否作为论文的最终系统，还是更适合作为单模型之外的补充实验？怎样证明提升来自模型之间的有效互补，而不是在Dev上反复挑选成员和轮次？是否需要固定组合后做多种子、按文本对分组的显著性检验，以及报告6个模型的推理成本？

### 3. 如何提高independent，让pair-aware更多起辅助作用？

**我们现在最困惑的是：同一套权重，单行判断较差，合并正反两行后却很好。** independent是每行直接在F/B/E/N四类里选最高分；pair-aware则把两行合起来，只在FB、BF、EE三个组合中选择，单例仍由模型自己预测。

原0.938版本的independent F1只有 **0.5472**，但pair-aware达到 **0.9381**。独立预测中，554条非N样本有 **297条被判成N**。本次S14也有类似现象：独立时F/B/E答对 **247/554**，pair-aware后变成 **534/554**；N仍为 **101/106**。因此，最终高分很大程度上依赖结构解码，不能直接理解成模型的单行四分类能力已经达到96%。

**训练目标可能是其中一个原因。** 当前两阶段训练先做单行四分类Row CE，再做三组合Pair CE。Pair CE用金标教模型哪个组合正确，但候选里没有N。对同一行的F/B/E分数同时加减一个数，Pair CE不变，独立预测却可能从正确标签变成N。阶段评估中也确实出现过Pair后独立分下降、非N误判为N增加的情况。不过，这个损失只是没有约束该方向，并不意味着它必然把所有F/B/E分数压低。

我们已试过混合Row／Pair训练、加入NN组合、保持Row输出、梯度协调、冻结、LoRA和权重平均等。部分方法能把独立分恢复到约 **0.84—0.86**，但结构分通常没有同时超过原0.938版本。这说明缓解训练退化和提高最终分数是两件事，独立判断还存在泛化问题。例如一个纯Row冻结版本在Train上的独立F1约 **0.9974**，Dev只有 **0.8485**；即使不用Pair CE，也不能消除这个差距。

想请教：下一步应怎样区分“训练使四类分数失衡”和“模型没有学会新表达的语义边界”？是否应把Row CE作为持续保留的主目标，让Pair只做辅助，并用独立分和结构分共同选模？对于剩余的E与F/B混淆、N与非N混淆，应该优先补充经过审核的对照样本，还是调整模型的比较方式？论文中又该怎样同时报告单行能力与结构解码收益，避免只用最高结构分描述模型能力？
