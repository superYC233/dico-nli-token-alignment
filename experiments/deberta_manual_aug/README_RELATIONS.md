# 新48行：两种训练安排

沿用0.935493那版的模型、NLI初始化、完整参数训练、Token Alignment、损失权重和选模指标。
数据是官方Train3042 + 原scope200 + 本次48 = 3290行，不叠加上一批120。

## 直接运行

先运行 `train_relation_staged.py`，再运行 `train_relation_mixed.py`。两个脚本各启动一次训练，不自动连跑。

| 入口 | 默认RUN_NAME | 训练安排 | 每轮优化步数 |
|---|---|---|---:|
| train_relation_staged.py | run06_relation48_staged | 全部Row CE，再全部0.5×Pair CE | 206+87=293 |
| train_relation_mixed.py | run07_relation48_mixed | 混合组，一次前向同时Row CE+0.5×Pair CE | 120 |

两个入口共用 `train_relation_manual.py`。超参数在共用文件顶部；RUN_NAME和AUGMENT_MODE在各自入口顶部。
默认 `AUGMENT_MODE='manual'`。可切为 `copy`（复制48行、类别/配对预算一致）或 `baseline`（只用旧3242），切换时换RUN_NAME。

权重根目录：`D:/model/SEAMEVAL/deberta_manual_aug/<RUN_NAME>/best_model.pth`。
结果：当前目录的 `outputs/<RUN_NAME>/`。
每轮保留预测和评分；只有Dev pair-aware Weighted F1刷新纪录时覆盖唯一最佳模型。训练结束后测原来的200条诊断题，不用诊断选模。

## 新样本是什么

`relation_examples.csv` 有30个源对照，展开为48行，F/B/E/N各12。
F/B/E以真实互换行组成pair，N仍保持单例。

- 真正增加限制：空间框架里的修饰、时间范围、动作对象限制；另有少量新闻航空词的同词数上下位。
- E：空间关系改写、前后置修饰、参与者不变的动作改写、月份前置与后置时间结构。
- N：关系角色、论元、事件、独立属性变化；因果相关不等于蕴含。

全部用词在官方Train中有可定位出处，记录在 `prepared_relations/train_word_sources.csv`。
这是重组已有用词和表达方式后的新设计，不是从Train直接取得这些整对及其金标。
标签理由逐条列出普通词义、空间/时间读法等假设，仍属于助手设计草稿，未经独立人工仲裁。
严格隔离会排除许多冠词和助动词，因此保留短语/标题片段风格，不用不自然从句凑数量。

`prepare_relation_data.py` 只用Dev文本做拒绝黑名单，不读取Dev标签。
本次新增48行与Dev的词形、Porter词干、整短语、无序文本对交集均为0，功能词也计入。
旧Train、旧scope200和copy对照单独披露，它们不满足新增人工词汇隔离规则。
方法方向受Dev错误分析影响，应披露；不能把文本零重合说成完全没有Dev开发影响。隐藏Test尚不可核验。

## 关于顺序

旧版的Row和Pair DataLoader已经分别 `shuffle=True`，每轮都会随机打乱。
本次仍打乱；两阶段Row/Pair沿用原版的全局torch随机数，混合版使用独立且持续推进的生成器。
不在每轮重新设同一个种子，Dev评估保存/恢复随机状态。
混合版打乱的是pair/N单例这些组，一对的两行保持同批，F/B/E/N混在一个训练流程中。

两阶段版末尾的Pair步骤只有FB/BF/EE，不见N，也没有Row CE；共享参数仍会被更新。
混合版同一步计算四类Row CE与Pair CE。N只进入Row CE；Pair CE自身仍没有N-logit的直接梯度。
随机混合不保证每个batch都有N，日志会记录不含N的批次数；每个N单例每轮仍只参与一次Row CE，不额外复制。

这两版并非纯粹改CSV排列：混合版还改变batch组成、优化步数、前向曝光。
两版每轮都让每行参与一次Row CE、每个真实pair参与一次Pair CE。
但两阶段额外前向计算配对行，前向总行数6050；混合版共用输出，前向总行数3290。
混合版的16是组数，最多32行；两阶段的Row批次16行，Pair批次16组。不要把两版称作有效batch相同。
run_config和逐轮日志均记录这些差异。不能把最终差距全部归因于“打乱顺序”。

两阶段沿用历史0.935的Row/Pair全局RNG用法；新48行会改变批次与随后的更新轨迹，不承诺复现旧曲线。
要单独归因新48行，可在同一入口用baseline模式对照。
两版虽然都写0.5，联合损失中的梯度权重与单独AdamW步骤的缩放并不代表完全相同的有效优化贡献。

## 检查

运行 `check_relation_setup.py`：只在CPU准备数据、编码文本，检查分组、逐轮打乱、曝光计数和合成logits的梯度；不训练DeBERTa。
两个训练入口均支持 `--prepare-only`，只准备数据和打印预计步数。

## 对近期结论的界限

人工120相对复制120多错的10行中，8行属于E；这能提示检查E判据，但不能证明原因只在48条E样本。
因为两版的F/B/N样本内容也变了，参数共享，其他类样本也能影响E。
pair-aware后的金标E行不会被预测为N，因此应同时查看独立预测的混淆矩阵，不能用解码后E→N的零数量验证阈值假设。
相同200条旧诊断题的基线已补测：原152、人工174、复制188；这些标签未经独立审核，是建议标签匹配数。
该200条不是新人工120行的训练拟合率，不能混为一谈；也不能根据一个诊断分数高低直接决定加量。
