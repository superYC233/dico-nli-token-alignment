# 首批实验：反向监督是否胜过等量重复

说明：`python`指已安装项目依赖的解释器。示例中的`model/`、`pretrained_models/`和`model_cache/`为通用目录，实际保存与缓存位置以配置项为准。

本目录先准备来源划分、监督视图与检查，不启动训练。研究设计从上一轮的24次联合头比较收敛为 **12次同模型比较**，先回答一个问题。

## 只改变第二个监督视图

使用现成的 DeBERTa NLI 初始化、CLS＋Token Alignment 和 Q/V LoRA，不新增分类头。两臂共用初始化、训练来源顺序、更新步数和损失归一化。

| 设置 | F/B/E 来源的两个输入 | N 来源的两个输入 |
|---|---|---|
| repeat_original | AB、AB，各自编码并经过随机 dropout | AB、AB |
| reverse_view | AB、BA，使用已有合法反向标签 | AB、AB |

两份 AB 不能复用同一 logits；那样不能控制编码和随机扰动的成本。每个来源先把两个 CE 平均，再对来源平均。第一批类别权重均为1，不加 Pair CE、KL、增强或推理时的 N 排除。

每档原向标签 F/B/E/N 各占四分之一，所以 A/B 的监督类别计数也相同。两臂主要差异是第二次训练看到新的输入方向还是重复输入。反向增强是必要基线，不作为方法创新。

## 来源与预算

`prepare.py` 只读官方英语 Train 和 Dev，不改原 CSV。Dev 文本仅用于隔离重复，Dev 标签不参与排除、抽样或选模。

1. 同一 pair_id 和规范化无序文本键涉及的来源合并为泄漏组件。
2. 预先隔离同向标签冲突组件及与官方 Dev 文本重复的组件。
3. 重复组件按预定的 pair_id 字典序选择一个完整来源，记录所有被合并的来源。
4. 固定256个来源为协议保留集；它们来自历史已使用的 Train，不是历史未接触的独立测试。
5. 每个抽样seed另取32个验证来源，构造64/128/256个训练来源的嵌套清单。

首批只跑64和256，128留待后续补曲线。训练＋验证标签成本分别为 **96和288个来源**；另有256个来源的评估标签，分开披露。标准离线分层抽样使用已有金标分组，不等于真实无标签主动选择。

抽样seed为101、202、303，训练seed首批固定42。共 `2预算 × 2设置 × 3来源抽样 = 12次`。关键设置后续再换训练seed，不能用这12次单独估计优化随机性。

## 正式训练前的实施顺序

`pilot_protocol.json` 记录候选优化配置和12次实验。训练runner尚需单独接入新的来源清单与视图，不直接运行历史增强训练入口。

1. 完成无更新检查：来源隔离、标签反转、N处理、来源损失及梯度、相同初始权重、保存重载。
2. 做一次明确标成 smoke 的50步试训，只检查训练拟合、时间、实际显存和精度兼容性，不评估保留集或官方Dev。该运行不进入主表。
3. 验证后冻结执行配置。起步候选为LoRA r16、lr1e-4、400个更新步、每步8个来源、每来源两视图；显存受限时可先用每microbatch两个来源并累积4次。以上不是已验证的最优设置。
4. 先做seed101的两个预算、两臂，共4次；完成正确性核查后再完成其余8次。
5. 首批报告固定末步结果。32个验证来源只作有限监控，不从大量checkpoint中挑最高分。固定末步避免选模噪声，但训练步数是否充分仍需训练拟合检查。

主指标为不读取分组信息的独立四分类 W-F1；同时记录macro-F1、按来源平均的准确率、原向/翻转分别表现、N错误、E/FBE边界、时间和显存。官方联合解码仅作后续分开的诊断。

输入视图数相同不代表墙钟耗时绝对相同。记录实际token数、padding长度和耗时，不能据单一显存配置承诺总训练小时数。

## 如何根据结果作下一步判断

- 实现、来源、类别计数或成本不匹配：先修协议。
- 两臂训练都拟合不了：先修基础训练，不能推断反向监督没有价值。
- 训练拟合好、保留来源都差：先查语义泛化错误，暂缓新增结构。
- 反向臂仅某个来源抽样或仅联合解码更好：补关键重复，暂不声称提高标注效率。
- 反向臂稳定提高独立分类：加入“反向监督＋软一致性”一臂，检验结构正则是否超出免费增强；再扩到独立任务。
- 差异小或波动大：表示目前没有证明额外收益，不足以证明两种训练等效。

这12次用来决定研究方向，完整投稿仍需更多预算点、训练随机种子、最接近方法及外部独立评估。
