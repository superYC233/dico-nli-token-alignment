# DiCo-NLI：给未来自己的完整回顾

这个项目一直在解决一个问题：两个英语短语，到底是意思一样、一个比另一个包含更多信息，还是属于其他关系？

例如，“火车站”一定是“车站”，但“车站”不一定是“火车站”。这和“汽车”“轿车”之间的信息范围有关，不只是两个词看起来像不像。我们把关系分成四类：正向蕴含 F、反向蕴含 B、等价 E、其他 N。

这份回顾按当时的思路写：先发现什么问题，为什么改，改完得到什么。数字来自完整实验记录。最后确定的方案仍然是 **DeBERTa-v3-base + Token Alignment + Real Pair CE + Pair-aware inference**，官方 DEV Weighted F1 为 **0.9248**。

## 一、从最开始到最终版本

### 1. DeBERTa baseline：先让模型把四类分出来

最开始做过 BERT、DeBERTa 的普通四分类。把两个短语一起输入模型，取一个代表整体输入的 CLS 特征，再接一个分类层，给 F、B、E、N 各打一个分。哪个分高，就选哪个。BERT 的准确历史成绩没有完整保留下来，所以这里不补猜。

DeBERTa baseline 保存的 DEV Weighted F1 约为 **0.8438**。它已经能学到不少语义关系，但每条输入基本是独立判断的。数据里明明有同一对短语的正反两个方向，模型却可能一边说“单向蕴含”，反过来又说“等价”。

这提醒我们：先不急着换更大的模型，数据本身还有一层现成的信息没有充分利用——正反向答案应当互相配合。下一步就从输出时利用这个关系开始。

### 2. Pair-aware：输出时，两个方向一起选

假如模型说 A 比 B 信息更多，那么交换顺序后，答案应该跟着从 F 变成 B。假如两边等价，交换后仍然是 E。既然这两条记录属于同一组，就可以把它们的分数放在一起看。

于是，对完整配对的两条记录，输出时只选 **F/B、B/F、E/E** 这三种组合。这样就不会出现“一个方向说单向蕴含，另一个方向却说等价”的矛盾。没有配对的记录仍按四分类分数预测，绝不是“没有 pair 就直接判成 N”。

对应保存结果到了 **0.8977**。这说明联合看两个方向很有价值。不过，这一步主要在模型已经打完分之后工作，模型训练时还不一定理解整组关系。我们因此继续想：能不能训练时也一起教？

### 3. 普通 Pair CE：训练时加上交换方向

第一次尝试比较直接：拿到一条 `(A,B)`，再临时构造一条 `(B,A)`。对于 F/B/E，让模型同时看正反向，然后检查这两个答案组合起来对不对。原来的四分类训练也保留。

这个版本保存的结果约为 **0.8966**，没有明显超过前面的 pair-aware 结果。因此，“把交换输入加进训练”本身并不保证提升。并且原数据本来就有不少正反两行，如果每行都再生成反向，同一个关系会重复出现。

下一步就更贴近原数据：不用每次临时造反向，而是根据真实 `pair_id`，把官方已经给出的那两条记录找出来。这样每组是什么、训练多少组，都更明确。这就是 Real Pair CE。

### 4. Real Pair CE：把真实的两个方向作为一组来学

用项目中的关系例子理解：

```text
A = conservative opposition
B = conservatives

(A,B) = FORWARD
(B,A) = BACKWARD
```

普通四分类相当于把这两道题分开批改：第一条有没有答 F，第二条有没有答 B。Real Pair CE 多做一件事：把同组两条的分数放到一起，问“整组应该是 FB、BF，还是 EE？”它利用的是**两条真实记录之间必须互相对应的关系**。

代码里的组合分数其实很直白。`logits`就是模型给各个类别打的分，还不是概率：

```python
score_fb = logits1[F] + logits2[B]
score_bf = logits1[B] + logits2[F]
score_ee = logits1[E] + logits2[E]
```

比如上面的例子，第一条的 F 分数加上第二条的 B 分数，应该比另外两种组合高。如果不够高，训练就推动模型朝正确的整组答案调整。两条记录顺序换了，目标也会从 FB 变成 BF；这里不是要求所有 pair 都固定写成 FB。

对应成绩达到 **0.9030**。普通四分类没有被替换掉：最终每轮先把所有行做一次四分类训练，再把真实 pair 做一次组合训练。当前 N 大多只有单行，也不属于 FB/BF/EE，所以仍主要靠四分类 CE 来学。分数上去了，但 N 漏判和 E 混淆还在，于是继续调整训练时关注各类错误的程度。

### 5. N weight：让模型更在意 N 的错误

当时有一部分真正的 N 被模型误认为存在蕴含或等价关系。于是把 N 的分类权重设为 **1.5**，意思是同样答错一条，让 N 的错误对训练更有影响。它没有增加新样本，也没有在预测时直接指定 N。

这一系列实验中，成绩从约 **0.9030** 到了 **0.9078**。但继续加到 1.75，保存结果反而约为 **0.8964**。所以权重是帮助模型分配注意力，不是越大越好；最后保留了 1.5，再去处理 E 和方向关系的混淆。

### 6. EE weight：让等价组合也受到足够重视

Pair 训练有 FB、BF、EE 三种答案。当模型容易把等价组错当成方向组时，很自然会想到：是不是应该让 EE 答错时受到更大的惩罚？于是把 EE 的 Pair 权重设为 **1.25**。

这个阶段保存的成绩到了 **0.9124**。要记住，N weight 作用在四分类训练里，EE weight 作用在三种 pair 组合的训练里，二者不是同一个开关。加权能改变学习重点，但没有直接教模型什么叫“只换说法”和“真的增加信息”，所以后面仍然需要更好的语义表示。

### 7. NLI-pretrained DeBERTa：换成已经学过蕴含任务的底座

前面用的是普通 DeBERTa-v3-base。后来换成已经在多种 NLI 数据上训练过的 base 版本，相当于找一个已经接触过“蕴含、矛盾等语义判断”的起点，再适应我们自己的四分类任务。

结果约为 **0.9133**。这里不是把原模型的标签直接拿来用，我们仍然有自己的 F/B/E/N 分类层。提升不算巨大，但它成为后续主线的底座。接下来考虑的是：模型会不会在小训练集上对某一种 pair 答案过于自信？

### 8. Pair label smoothing：训练时别逼模型过度自信

原来的 Pair CE 强调正确组合，label smoothing 则把目标稍微放软一点：正确答案仍占绝大部分，但不给其他组合绝对的零空间。最终使用 **0.05**，希望减少模型死记训练样本、把分数拉得过于极端。

对应保存结果是 **0.9160**。以前讨论时有过分数归属混淆，这里记住它不是 0.9248。平滑以后 Pair loss 不一定接近零，也不能仅凭 loss 还在 0.3 左右就说没学会。此时主要问题仍是 E 和 F/B，于是我们开始显式比较两边的具体词。

### 9. Token Alignment：让模型看清两边到底哪里相同、哪里不同

#### 为什么要在 CLS 之外加一条比较路径

CLS 把整个输入概括成一个向量，适合做整体判断。我们希望再提供一份更具体的信息：哪些内容能对应，哪些内容只出现在一边，哪些是换了说法。DeBERTa 本身已经会结合上下文，这个改动是在它的基础上，增加一条明确做比较的路径。

下面一直用这个例子：

```text
A = "train station"
B = "station"
```

直觉上，`station`与`station`对应，而`train`增加了限定。模型需要判断这个限定有没有改变信息范围。下面的描述是希望它学会的比较方式，并不是说我们已经把这个例子每一步的内部判断都观察出来了。

#### 第一步：DeBERTa 给每个 token 一份特征

两个短语放在同一个输入里，经过编码器后，每个位置都有一串768个数。可以把它理解成这个位置的“语义笔记”：既包含词本身，也受到附近词和另一段文本影响。

这些位置实际是 tokenizer 切出来的 token，有时是整词，有时是子词。为了便于理解，我们把它们叫“词”。输入是一组文本对，输出是一排向量，而不是直接得到“train多余”这样的文字结论。

#### 第二步：768维压到128维

每个位置的768个数再通过一个可训练的转换层，变成128个数。好比从较长的语义笔记里提取一份专门用于比较的摘要。

这样后面的匹配和比较计算更轻，也让模型学习什么信息对对应关系有用。128维并不神奇，也不能保证完全不丢信息；它是当前成功版本采用的大小。

#### 第三步：先分清 A 和 B 的位置

输入里除了正文，还有表示开头、分隔和补齐的特殊位置。代码利用分隔符和有效位置标记，找出哪些 token 属于 A，哪些属于 B。

对这个例子，A保留`train station`，B保留`station`。后面的比较不把补齐位置算作真实内容，也不把分隔符当成对侧的一个词。否则模型可能把注意力分给没有语义作用的位置，平均结果也会被干扰。

#### 第四步：A 去 B 找对应，B 也去 A 找

代码比较两边128维向量的相似程度，再把相似分数变成权重。A中的`station`可能会高度关注B中的`station`；B中的`station`则可能更关注A中的`station`，同时也分一点权重给其他位置。

这叫软对齐：不用硬选一个词，而是把对侧相关内容按权重混合成一个128维向量。temperature是0.1，会让较高相似度的位置更突出。这些权重表示“参考对方哪里”，不是“蕴含成立的概率”。

还有一个很重要的限制：原版没有“这里没有对应词”的选项。如果B只有`station`，A中的`train`也必须从那里取到匹配内容。所以模型不是直接得到一个空格，而是通过接下来的比较，发现这种匹配与自身内容之间可能存在差异。这也是后来想做NULL的原因。

#### 第五步：把自己和对应内容放在一起比较

每个token会准备四份信息：

```text
tokens             自己的128维特征
aligned            从对面加权取来的128维内容
tokens - aligned   两边在哪些特征上有差别
tokens * aligned   两边特征的逐项交互
```

`tokens`保留“我本来是什么”，避免只知道差了多少却忘记比较对象。`aligned`保留“对面提供了什么”。例如`train`对着`station`，与`station`对着`station`，即使都有匹配权重，具体比较内容也不同。

差值提供有方向的差异线索，谁减谁是有区别的；乘积提供两边特征共同出现或相互作用的线索。它们都是供后续学习的数字，不能简单理解成“差值大就一定F、乘积大就一定E”。同义词也可能有表示差异。

四份128维拼成512维，再经过比较层压回128维。输出可以理解成“这个位置与另一边比较后的摘要”。A和B共用这套比较方法，但两边摘要会分开保留，所以方向信息没有被直接合并掉。

#### 第六步：把一排比较结果汇总

现在每一边仍然有很多token摘要，而分类需要固定长度的输入。代码使用两种汇总：mean pooling看所有有效位置的平均情况，max pooling在每个特征维度上保留最强信号。

平均能看整体对应得怎么样，最大值可能保留某个位置突出的差异。max并不是完整挑出“最重要的一个词”，不同维度的最大值可能来自不同位置。两者各128维，拼成一侧256维；A和B再拼成512维。

#### 第七步：得到 match_logits，再和 CLS 相加

整个A/B的比较摘要经过匹配分类层，得到F/B/E/N的四个分数，叫`match_logits`。原来的CLS也有四个分数，最后相加：

```python
final_logits = cls_logits + match_logits
```

保留CLS，是因为总体语境仍然有用。Token Alignment负责提供具体对应和差异线索，两条路径互相补充。比如`car`与`automobile`词面不同，整体语义信息可能帮助判断它们只是改写；不能只看局部不一样就判成单向蕴含。

匹配头最后一层最初设为零，让新分支刚开始输出零分，不马上用随机分数干扰原分类路径。随着训练，它逐渐学会怎样补充分类。只是新分支的最后一层从零开始，不是整个模型都从零学；CLS四分类头也仍需要适应任务。

加入这条路径后，主线达到 **0.9248**。这给了我们一个明确方向：显式比较两侧内容值得保留。但它仍可能看到差异却判断错差异的意义，后续许多尝试就是围绕这个问题展开的。

### 10. 最后回到原版，确认可以复现

后面试了不少结构和数据增强，分数有升有降。最后关闭增强，重新用官方完整3042行训练、660行DEV评估，又得到 **0.9248**，保存的预测与原基线一致。

所以最后锁定普通Token Alignment这条主线，不再把所有尝试堆进去。Seed是42，训练10轮，最佳第7轮。这里的0.9248是最终选定方案的成绩，不是声称每次运行都能达到，也不是历史全部实验数字的最大值。

## 二、分数是怎么一步一步涨上来的

这是方法发展的路线。不同阶段并非都做了严格的单变量、多seed比较，因此不能把每一段差值都当作某个模块确定的净贡献。

```text
DeBERTa baseline                         0.8438
  ↓ 输出时让两个方向互相配合
Pair-aware                              0.8977
  ↓ 尝试训练时加入交换方向，尚未明显改善
普通 Pair CE                            0.8966
  ↓ 改为使用数据中的真实反向组
Real Pair CE                            0.9030
  ↓ 更重视漏判的 N
N weight = 1.5                          0.9078
  ↓ 更重视等价的 pair 组合
EE weight = 1.25                        0.9124
  ↓ 使用已经学过 NLI 的底座
NLI-pretrained DeBERTa-v3-base           0.9133
  ↓ 放软 Pair 训练目标，减少过度自信
Pair label smoothing                    0.9160
  ↓ 增加两边 token 的显式比较
Token Alignment                         0.9248
```

## 三、后来还试了什么，但为什么没用上

### Large：会不会只是 base 不够强？

当时很自然地怀疑模型容量不足，所以换更大的NLI预训练DeBERTa。Large alignment约 **0.8987**，Large加NULL约 **0.9083**；后一组跑完10轮，最好仍在第3轮，没有因为多跑几轮追上base。

这些配置更慢，也没有达到目标，因此没继续选它。不过Large的batch、学习率等也不同，不能由此断言Large天生不如base，只能说我们当时那几套配置不划算。

### ModernBERT：换一种底座有没有新机会？

这次想验证的不只是大小，还包括另一种模型和NLI预训练方式。确实留下了对应脚本，但目前没有找到能确认的准确成绩。

因此只能记“试过，缺完整结果”，不能编成某个低分，也不能用它替换已经复现成功的基线。

### NULL alignment：让 token 可以说“我没有对应”

原版里，即使`train`在另一边只有`station`可看，它也必须分配匹配权重。NULL就是给它增加一个选择：另一边没有真正对应内容。

思路很贴合额外限定词的问题。NULL-M在seed42曾达到 **0.9290**，确实高于0.9248；但seed7约 **0.9101**，没有建立稳定优势。我们最终保留普通对齐，是选择更简单、已复现的主线，不是说NULL从来没涨过分。

### Attention pooling：让模型重点看关键差异

平均可能把关键位置冲淡，所以尝试让模型自己给位置分配重要程度。比如让它更关注`train`，而不是被两边相同的`station`主导。

结果约 **0.9198**。F/B→E从20条降到14条，但E→F/B从16条升到22条，两项合计仍是36条。看起来模型更容易强调差异，却没有同时分清哪些差异只是合法改写，因此没有选。

### Conv composition：先把附近几个 token 合起来看

这个尝试针对“逐token比较完就池化”：`train + station`作为一个短语的含义，可能比两个位置分开看更重要。于是尝试让相邻比较特征先交流，再汇总。

对应compose结果约 **0.9187**，没有超过基线。它提醒我们，补一个看起来合理的结构不一定解决真正缺口；DeBERTa本身也已经带有上下文信息。

### Prototype：每类找几个代表性的样子

一个类别可能包含不同情况，所以试过用多个“代表点”帮助分类。可以把它想成：等价关系不只长一种样子，给它几种参考模式。

保存的k1约 **0.9087**，k3约 **0.8987**。增加代表点没有带来预期收益，所以没有留在最终模型里。

### Hierarchical：把四分类拆成几步判断

这个方向想先判断是否存在相关关系，再判断方向或等价，希望每一步更容易学。保存结果约 **0.8840**，没有达到主线水平。

相关源码后来改过，训练细节也不止一个变化，因此不能总结成“分层一定不好”。只能说当时这套拆法和训练过程没有成功。

### Augmentation：是不是边界例子太少？

模型分不清等价改写和额外限定，可能与训练例子不足有关，所以我们补过边界数据。早期manual增强曾达到 **0.9335**，一度让人觉得找到了最有效的方法。

但这批历史数据存在DEV参与构造的来源问题，不能因为分高就忽略它。后来改成仅由训练关系出发、检查与留出数据重合的24对增强，共48行；在完整官方训练协议下结果约 **0.9148**。

这批数据让E和N的一部分指标变好，却把更多F/B判成E，总体没有提升。因此最后不加增强。结论不是数据永远没用，而是质量、来源和两种关系的平衡，比单纯增加数量更重要。

### Boundary Loss：直接教“方向关系还是等价”

既然主要错在F/B和E之间，当时就想：能不能额外给一道二选一题，直接区分directional和equivalence？这不需要新增标签，用现有标签就能构造。

保存结果约 **0.9145**。F/B→E从20减少到12，但E→F/B从16增加到32。它更倾向选择方向关系，却让边界错误总数增加。

这次结果更像把选择偏好推向一边，没有带来同时改善的证据。不能据此断言模型内部完全没学到新东西，但作为最终方案没有收益，便放弃了。

### Bi-Entailment：拆成两个“是或不是”会不会更清楚？

这个想法很自然：分别判断A是否蕴含B、B是否蕴含A。只有前者成立是F，只有后者成立是B，两个都成立是E，两个都不成立是N。

但对应结果约 **0.8520**。N只正确77/106，而且有44条真实非N被判成N。两个判断没有形成更好的四分类结果，保存预测的解码行为也与最终版本不同，所以这次没有采用。

要记住：两个二进制答案当然能表示四类，并不是数学上“不可能”。问题可能在独立判断的限制、训练和组合方式；这次失败不能替所有双向蕴含方法下结论。

### Entailment Auxiliary：保留四分类，再补两道蕴含题

纯二元效果差，于是又尝试保留四分类，同时额外强调A→B、B→A的判断，希望它帮助模型理解F/B/E之间的联系。

保存结果约 **0.8837**，E变差，N只正确78/106。不过当前这版实现还取消了Real Pair CE训练，并不只是原模型上多加一个辅助loss。因此不能把所有下降都算给辅助任务；能说的是，这套实际运行没有胜过最终版本。

## 四、最后到底还错在哪里？

最终660条预测中错了50条，可以拆成四种情况：

| 错误 | 条数 | 大白话解释 |
|---|---:|---|
| F/B→E | 20 | 明明一边多了信息，却当成完全等价 |
| E→F/B | 16 | 只是换一种说法，却以为有信息增减 |
| F↔B | 6 | 知道是单向关系，但方向选反 |
| N错误 | 8 | 本应属于其他关系，却判成蕴含或等价 |

前两项一共 **36/50=72%**。这说明真正难点主要是等价和信息范围变化之间的界线，而不是简单地把方向反了。

`train station`与`station`是信息范围变化；`car`与`automobile`在合适语境下虽然用词不同，却可能仍然等价。这些只是帮助理解的例子，不是说它们一定属于当前DEV错题。

Token Alignment提供了观察差异的路径，但看到不同不等于理解不同。下一步真正要解决的是：这个差别究竟只是改写，还是确实改变了谁包含谁。Attention和Boundary的实验都说明，只把差异强调得更强，可能顾此失彼。

## 五、当时踩过的坑

**把clean和官方DEV混着比。** clean valid是从官方训练集另外划出的612条，官方DEV是660条；模型训练时看到的数据量也不同。clean的0.9398不能直接说比官方DEV的0.9248更强。最终回到完整官方train/DEV，并保留官方原始训练数据。

**把DEV当成从没见过的test。** 我们反复用DEV选结构、参数和epoch，它已经参与开发决策。最终分数是开发成绩；若要判断真正的泛化，还需要独立评估。

**看文件名猜配置。** Boundary目录写着0p3，当前代码实际是0.1。原token脚本后来改成GELU，最近成功复现脚本用ReLU。文件名没变，不代表代码没变；不能拿今天的源码解释过去每一次运行。

**把低loss当成一定更好。** 最终模型第7轮最好，第10轮DEV却只有约0.8805。标签平滑、focal等loss定义也不同，绝对数字不能随意横比。只盯训练loss会误判方向。

**把一次高分当成稳定提升。** NULL曾有0.9290，但不同seed会波动。Large也没有因为容量更大就自动赢。单次小涨值得记录，却不足以宣布取代基线。

**被manual高分吸引，忽略来源。** 如果增强内容参考了DEV错误，再用同一DEV评估，就不能把提升全当成对陌生数据的能力。后来排除相同文本，也不能替早期构造过程消除影响。

**把SoftCons=1当成模型自己全学会了。** pair-aware只允许三种兼容组合，这本身就能保证完整pair的输出一致。答案可以互相兼容但同时错误，还要看F1和整组是否真答对。

## 六、最终模型完整流程图

```text
             text1 + text2
                   │
          NLI DeBERTa-v3-base
                   │
        ┌──────────┴───────────┐
        │                      │
       CLS                Token Features
        │                      │
   4-class logits         768 → 128
        │                      │
        │                 双向 Alignment
        │                      │
        │                Token Comparison
        │                      │
        │                mean + max pooling
        │                      │
        │                 match_logits
        └────────── + ─────────┘
                   │
           final 4-class logits
          ┌────────┴──────────┐
          │                   │
        Row CE            Real Pair CE
       所有训练行          同组两行的分数组合
                          FB / BF / EE

推理：final logits → pair-aware → F / B / E / N
```

左边看整体语义，右边显式比较两侧内容，相加得到最后分数。训练分两段：每轮先完整跑Row CE，再完整跑Real Pair CE，并不是每个batch同时计算图中两个loss。

主要设置保留为：row batch16、pair batch16组、最大长度128、学习率2e-5、N权重1.5、EE权重1.25、Pair loss权重0.5、Pair平滑0.05。最终没有NULL、额外辅助任务或增强样本。

### 任务是什么？

判断英语短语对是正向蕴含F、反向蕴含B、等价E，还是其他N。重点是“差异有没有改变信息范围”。

**DeBERTa-v3-base（NLI预训练）**，加上：

- **Token Alignment**
- **Real Pair CE**
- **Pair-aware inference**

### 最大问题和下一步是什么？

50条错误里36条是E与F/B互相混淆。Large、NULL、attention、Conv、原型、分层、Boundary、二元蕴含、辅助任务和增强都试过，别忘了旧结果又从头盲试。
