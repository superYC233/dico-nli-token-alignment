# Le Duc Minh 的 DiCo-NLI 公开方案：中文阅读报告

整理日期：2026-10-26。

这份报告解释作者公开说明中的方法与成绩，方便理解和交流。内容来自网页阅读，没有下载保存或运行对方的代码、模型权重；没有独立复现其结果。作者提到的最终集成成员文件尚未取得，不能把文档里写出的文件路径当作已经看到文件内容。

## 一、先看结论

这个项目采用的主线是：**NLI 预训练模型微调，结合正反方向的分数，再探索多模型集成和数据结构先验。**公开的约 0.961 英文成绩属于按 DEV 选择的集成系统，使用了结构先验，不能理解成某个单模型仅凭两个短语就有 96.1% 的独立判断能力。[作者模型说明](https://huggingface.co/LakoreAI/dico-nli-checkpoints)

目前没有证据据此认定作者把 DEV 标签用于梯度训练。文档明确披露了使用 DEV 选择模型组合；这种做法会使开发集成绩偏乐观。

## 二、它做的任务是什么

输入两个短语 A、B，判断等价 E、正向蕴含 F、反向蕴含 B，或者其他关系 N。F/B 交换方向后互换，E 保持不变。N 汇总其他关系，没有官方确定的反向标签，不能一般性地假设交换后仍然是 N。

作者特别研究了如何让两个方向的预测相容，也检查了分组方式是否透露类别信息。[作者研究说明](https://github.com/MinLee0210/dico-nli-challenge/blob/main/docs/RESEARCH.md)

## 三、用了哪些模型和训练方式

公开项目以 cross-encoder 为主：把两个短语一起输入编码器，由分类头输出关系分数。

| 主要骨干 | 用途 |
| --- | --- |
| mDeBERTa-v3-base，多语言 NLI 初始化 | 多语言任务的主要模型之一 |
| XLM-RoBERTa-large，XNLI 初始化 | 另一类多语言模型 |
| DeBERTa-v3-large，NLI 初始化 | 英文专用实验 |

训练流程包括普通分类监督，以及约束正反方向预测分布相容的 KL 损失。后者可理解为：把反向预测中的 F/B 交换回来，再要求它与正向预测接近。它与我们现有的 FB/BF/EE 三组合 Pair CE 不是同一个损失。

项目支持把同一来源的不同语言视图一起使用；这些视图共享语义来源，不能把每行都当成全新的独立例子。上述模型、训练与解码入口见[项目 README](https://github.com/MinLee0210/dico-nli-challenge)。

作者也试过额外数据和其他骨干，但不能把“试过的模型”全部算入最终集成。实验记录中，反向 N 增强、部分外部数据和部分骨干没有带来改善。[公开实验记录](https://github.com/MinLee0210/dico-nli-challenge/blob/main/docs/EXPERIMENTS.md)

## 四、正反方向如何共同判断

正向的 F 应与反向的 B 对应。因此，不能不交换标签就直接平均两行分数。

作者把正反预测变换到统一方向，合并 log-probability；也提供按来源分组合并语言视图的方式。[解码说明](https://github.com/MinLee0210/dico-nli-challenge#decoding-modes)

大白话示意：

```text
A→B 的 F 证据，与 B→A 的 B 证据合并
A→B 的 B 证据，与 B→A 的 F 证据合并
A→B 的 E 证据，与 B→A 的 E 证据合并
```

这种处理能保证输出按预定映射相容，但两个方向仍可能一起答错。一致性和正确性必须分开看。

## 五、最关键的数据结构先验

作者观察到，当前发布的数据中，可逆关系有反向记录，N 没有反向记录。其结构先验直接利用这个组织规律：

```text
找到反向记录：只在 E/F/B 中判断
找不到反向记录：直接输出 N
```

这样，单例的 N 判断由文件结构完成，不需要模型理解文本。作者在研究说明中讨论了这种规律及其适用边界，不能推定未来文件也一定如此组织。[数据结构讨论](https://github.com/MinLee0210/dico-nli-challenge/blob/main/docs/RESEARCH.md)

作者明确表示，该先验用于正式提交是否被允许，尚未获得组织者确认。不要把“当前数据上成立”解释成“已获官方许可”。[作者披露](https://github.com/MinLee0210/dico-nli-challenge#decoding-modes)

## 六、多模型集成与 DEV 选择是什么意思

多个训练好的模型分别输出关系分数，再合并，得到最后预测。同一种架构使用不同随机种子或不同训练配方，也会产生不同的集成成员。

明确公布的 **Clean-7** 包括 4 份 mDeBERTa 权重和 3 份 XLM-R-large 权重。另有 Prior-14，以及针对不同赛道在 DEV 上选择成员的版本。[集成组成说明](https://huggingface.co/LakoreAI/dico-nli-checkpoints#evaluation-dev-set)

“按 DEV 选择”可以理解为：比较不同成员组合在 DEV 上的表现，再保留表现好的组合。它没有自动等同于用 DEV 做反向传播，但会让组合针对这份 DEV 优化，未知数据上的收益需要另测。

**Clean-7 的组成已在说明中列出；约 0.961 那版的精确成员清单，目前没有取得。二者不能混为一谈。**

## 九、对我们当前项目意味着什么

下面是结合本项目的解释，不是作者论文结论：

1. 比较分数时，要同时说明单模型还是集成、是否使用文件结构、是否在 DEV 上选择成员。
2. 我们当前的 Pair-aware 排除了两行组中的 N，但单行组仍由模型四分类；对方结构先验进一步把单例直接判 N，设置不同。
3. 结构先验下的高分，不能直接证明模型更会区分语义等价和单向蕴含。
4. 我们已有大量相似实验，不应因为对方提到了 KL、WordNet、分层头或集成，就认为这些都是未尝试的新方向。

**阅读这个项目最有价值的收获，是弄清成绩由哪些环节组成，以及哪些结论还需要独立验证。不能只拿 0.961 一个数字评价模型能力，也不能仅凭高分认定作者训练了 DEV。**
